# Pattern comparison

| Pattern              | Problem and algorithm/state                                         | Concurrency and failure                                         | Performance                                              | Advantages/trade-offs                                            | Use, misuse and interaction                                               |
|----------------------|---------------------------------------------------------------------|-----------------------------------------------------------------|----------------------------------------------------------|------------------------------------------------------------------|---------------------------------------------------------------------------|
| Circuit breaker      | Repeated failures/latency; local state with bounded outcome history | Serializes short transitions; OPEN sheds; ignores local rejects | O(1) record; monitor contention                          | Fast isolation/recovery; cold-state and threshold tuning         | Dependency health; misuse: retries around permanently open circuit        |
| Retry                | Transient failures; bounded attempts and elapsed budget             | New attempt only with explicit safety; interruption stops       | Extra requests and delay; jitter reduces synchronization | Recovery from transient IO; duplicate effects if contract unsafe | Idempotent reads; combine with per-attempt circuit and bulkhead           |
| Semaphore bulkhead   | Concurrent resource exhaustion; finite permits                      | Interruptible wait, exact release on physical exit              | O(1) uncontended; contention/wait on saturation          | Cheap isolation; no CPU thread isolation                         | Blocking clients on virtual threads; never release on mere caller timeout |
| Thread pool bulkhead | Worker starvation; fixed workers and bounded queue                  | Abort rejection, cancellation cooperative                       | Scheduling/memory cost; queue adds tail latency          | Stronger execution isolation; many per-endpoint pools costly     | Legacy blocking work; implementation uses shared no-queue workers         |
| Timeout              | Latency runaway; monotonic deadlines and timed waits                | Cancels Future, physical work can continue                      | Scheduling/wait cost and abandoned work                  | Bounds caller wait; cannot kill arbitrary code                   | Transport waits; pair with physical permits and client timeouts           |
| Rate limiter         | Request rate/quota overload; token or leaky bucket                  | Atomic token consumption; rejects above budget                  | O(1) local, distributed coordination costs               | Controls rate, not concurrency                                   | Optional future extension; pair with bulkhead for slow calls              |
| Fallback             | Permitted degraded output; explicit business eligibility            | Runs after failure within remaining budget                      | Additional work/latency, cache footprint                 | Availability; stale/incorrect claims can harm users              | Recommendations; never invent payment/auth success                        |
| Load shedding        | Overload; immediate bounded admission rejection                     | Refuses work before allocating scarce resources                 | Low overhead; may reduce availability under bursts       | Protects local latency/resources                                 | Queue saturation; return controlled unavailable response                  |
| Backpressure         | Producer faster than consumer; demand and bounded buffering         | Upstream must honor demand/cancellation                         | Coordination and bounded buffering overhead              | Prevents backlog; needs end-to-end protocol                      | Reactive streams; blocking adapter here is not reactive backpressure      |
| Adaptive concurrency | Changing dependency capacity; latency feedback controller           | Updates concurrency with damping and floor/ceiling              | Feedback measurement overhead, oscillation risk          | Auto tuning; complex under mixed latency                         | Future extension after measured demand, avoid untested controller         |
| Health-aware routing | Partial instance outage; route by health signals                    | Stale signals and concurrent topology changes                   | Lookup/cache cost, health probe load                     | Avoids bad endpoints; can concentrate load                       | Service discovery/proxy; keep local breaker as last defense               |
